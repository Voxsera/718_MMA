# Deploying 718 MMA Gym (Render — recommended)

This app is **one Express service** that serves the React site + API + `/admin` and stores
data in a SQLite file. It needs a host with a **persistent disk**, so it runs as a single
web service (not on Vercel's serverless functions). Render and Railway both work; steps below
are for Render. The `render.yaml` blueprint automates most of it.

## 0. Prerequisites
- A **GitHub repo** with this project pushed to it.
- A free **Render** account (https://render.com).
- (For live login/payments) your **Google OAuth** and **Razorpay** keys.

## 1. Push to GitHub
```bash
cd "718 MMA Gym"
git init
git add .
git commit -m "718 MMA Gym"
git branch -M main
git remote add origin https://github.com/<you>/718-mma-gym.git
git push -u origin main
```
`.gitignore` already excludes `node_modules`, `.env` and `data.db`.

## 2. Create the service on Render
Easiest (uses `render.yaml`):
1. Render Dashboard → **New → Blueprint**.
2. Connect your repo and select it. Render reads `render.yaml`.
3. It creates a Web Service with a 1 GB disk mounted at `/data` and `DB_PATH=/data/data.db`.

Or manually (no blueprint):
- **New → Web Service** → connect repo.
- **Build command:** `npm install && npm run build`
- **Start command:** `npm start`
- **Add a Disk:** name `data`, mount path `/data`, size 1 GB.
- Add env var `DB_PATH=/data/data.db` and `NODE_VERSION=22.12.0`.

> The disk needs Render's paid **Starter** plan. On the **free** plan you can skip the disk and
> remove `DB_PATH` — the app still runs and **auto-seeds demo data on every boot**, but
> bookings/payments won't persist across redeploys/sleeps. For real data, use the disk
> (Render Starter) or a Railway **Volume**.

## 3. Set environment variables (Render → your service → Environment)
| Variable | Value |
|---|---|
| `ADMIN_USERNAME` | your admin user (e.g. `admin`) |
| `ADMIN_PASSWORD` | a strong password |
| `SESSION_SECRET` | auto-generated by the blueprint (or any long random string) |
| `JWT_SECRET` | auto-generated by the blueprint |
| `GOOGLE_CLIENT_ID` | from Google Cloud Console |
| `GOOGLE_CLIENT_SECRET` | from Google Cloud Console |
| `RAZORPAY_KEY_ID` | Razorpay key (test or live) |
| `RAZORPAY_KEY_SECRET` | Razorpay secret |

Leave Google/Razorpay unset to run in **mock mode** (login disabled, payments simulated).

## 4. After the first deploy
Your app is live at `https://<your-service>.onrender.com`.
- Site: `/`   ·   Admin CRM: `/admin`
- The DB auto-seeds courses/events/etc. on first boot.

Update your provider dashboards with the live URL:
- **Google Cloud → Credentials → your OAuth client → Authorized JavaScript origins:**
  add `https://<your-service>.onrender.com`
- **Razorpay:** use your live keys; no redirect URL needed (popup checkout).

## Railway (alternative)
1. railway.app → **New Project → Deploy from GitHub repo**.
2. Settings → **Build command** `npm install && npm run build`, **Start command** `npm start`.
3. Add a **Volume** mounted at `/data`, and a variable `DB_PATH=/data/data.db`.
4. Add the same env vars as the table above. Railway sets `NODE_VERSION` via `.node-version` (22.12.0).

## Why not plain Vercel?
Vercel runs serverless functions with a read-only, ephemeral filesystem, so the SQLite file
can't persist. To use Vercel you'd migrate the DB to a serverless option (Turso/libSQL, Neon,
or Vercel Postgres) and wrap Express as a function — ask if you want that path instead.
